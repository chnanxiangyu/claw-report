一、项目背景

金融Claw是一款 AI native 金融信息助手客户端，定位为"用AI能力帮普通用户读懂金融信息"的桌面端产品。区别于传统金融终端面向机构专业人士堆砌全量数据的产品范式，Claw试图解决的是金融信息消费链路的最后一步：理解门槛。数据获取的门槛在降低，但理解的门槛依然高高竖起。

我在实习期间深度参与了Claw客户端的产品迭代工作，核心职责覆盖用户调研设计与执行、产品需求梳理与优先级研判、Skill生态策略规划三个方向。本报告基于我主导的第一轮用户深度访谈（10位用户、75条问题记录），系统梳理了产品现状、用户核心诉求，并在此基础上形成了对产品方向的独立判断与反思。

岗位关联说明：本报告所述项目处于迭代推进阶段，尚未正式落地。但完整经历了从用户洞察 → 需求结构化 → 方向判断 → 策略修正的全链路产品思考过程，这些实战经验与反思，构成了我应聘AI产品经理岗位的核心能力凭证。
二、产品详情
2.1 产品定位

Claw的核心理念是：金融信息从来不缺，缺的是有人帮你读懂它。产品不仅聚合行情、研报、资讯等金融数据，更依托大模型能力对信息进行加工与解读，将海量信息压缩成有信息量的判断线索，帮助用户聚焦关键变化和值得关注的方向，而非丢给用户一堆可能性。

核心差异化：让过去只有机构才拥有的金融信息解读能力，变得更易懂、更个性化、人人可用。这不是做一个"更全的数据终端"，而是重新定义金融信息的消费方式。
2.2 目标用户
  • 核心用户：有主动投资行为、但对专业金融数据解读能力不足的个人投资者
  • 延伸用户：对市场有关注意愿、希望以低门槛获取个性化金融洞察的泛理财人群
  • 用户特征：习惯使用主流C端理财平台，对AI工具有一定接受度，但金融专业素养参差
2.3 产品架构

Claw客户端以AI对话为核心交互入口，围绕对话构建了五大功能模块，形成"信息获取 → 智能解读 → 主动服务 → 跨端协同"的完整产品闭环：

AI 对话

自然语言交互的金融问答入口，支持多轮对话、上下文记忆，可调用Skill执行分析任务

行情看板

实时行情展示，含基金/股票行情、板块轮动、资金流向，支持AI解读提问

技能广场（Skill）

可组合的金融分析技能集合，如实时估值、大V观点追踪、盈亏预测等，用户按需选用

定时任务

支持周期性/间隔性自动执行，实现"自动盯盘"，定时运行指定Skill并输出结果

微信联通

打通客户端与微信端的跨端协同链路，支持微信端发起对话、接收任务推送、上传图片等

2.4 核心功能模块说明

五大功能模块的定位与能力说明如下：

AI 对话：核心交互入口

自然语言金融问答入口，所有金融问答与分析任务均通过对话发起。支持多轮对话与上下文记忆，可调用Skill执行深度分析，并结合用户持仓与偏好输出个性化解读。

行情看板：信息展示与AI解读

聚合基金/股票行情、板块轮动、资金流向等实时数据，支持针对行情内容直接向AI提问，兼顾"看数据"与"问解读"两种使用方式，是用户感知最直接的"看"的模块。

技能广场（Skill）：可组合的分析能力

Claw区别于普通行情软件的核心差异化。每个Skill封装一个完整的金融分析能力，如实时估值、大V观点追踪、盈亏预测等，用户按需选用、按场景组合，实现"点开即用"的分析服务。

定时任务：自动盯盘能力

支持周期性/间隔性任务配置，定时运行指定Skill并输出结果，让产品从"被动问答"升级为"主动服务"，承载用户"自动盯盘 + 结果推送"的核心诉求。

微信联通：跨端协同

打通客户端与微信端的协同链路，支持微信端发起对话、接收任务推送、上传持仓截图等，降低用户打开客户端的门槛，构建随时可用的移动端使用场景。

3.3 三大核心发现
发现一：持仓记忆缺失，用户反复提到"想看自己的持仓"

当前客户端没有自动导入持仓/自选数据，用户无法基于自身持仓获取个性化行情和分析。这是用户感知最强的痛点所在：没有持仓记忆，Claw的所有分析能力都停留在"通用"层面，无法产生个性化价值。

迭代方向：将OCR持仓上传能力渗透到各功能场景，新用户首次对话引导上传持仓截图、微信端支持上传持仓截图、创建定时任务时推荐上传持仓并建立关联任务。目标是帮助用户快速建立持仓记忆，在各场景中持续产生个性化需求。
发现二：对话→定时任务→微信推送链路断裂

用户对定时任务的核心诉求是"自动盯盘 + 结果推送"，但当前链路在三个环节均存在断裂：对话中需强指令才能创建定时任务，定时任务结果无法推送到微信和对话框，用户需手动查看结果。

迭代方向：打通「新建对话 → 定时任务 → 微信推送」完整闭环：对话中自然语言直接创建任务，结果自动推送至微信并生成历史对话支持追问，微信端与客户端均可查看并继续追问。这是用户感知最强的组合场景，也是Claw区别于普通行情软件的核心差异化价值。
发现三：客户端偏重，需轻量化

多位用户反馈安装包体积大、打开慢、运行卡顿。作为一款AI辅助工具，过重的客户端显著影响首次体验和留存。

迭代方向：缩小安装包体积、Skill按需分批下载（非核心Skill不预装）、优化启动速度和运行性能。

四、调研反思

以下反思基于第一轮访谈的真实数据与体感，结合我在Claw项目中的完整产品实践，尝试回答三个问题：产品方向对不对、Skill生态怎么建、这段经验如何连接到AI产品经理的岗位要求。

4.1 产品方向反思：AI加工能力是壁垒，但场景闭环是前提

访谈数据给出了一个清晰的信号：用户最满意的模块是Skill（实时估值等主推能力），最想要的功能也围绕Skill展开（持仓导入与记忆、定时任务与微信联通、盈亏预测）。这说明Claw的差异化方向是对的，即用AI加工和解读金融信息。用户不需要又一个数据终端，他们需要的是"有人帮我读懂"。

但问题在于：好的能力没有嵌入到好的场景闭环中。用户买了最好的食材（Skill），却发现厨房的动线是断的（对话→定时任务→微信推送链路断裂），最终做不出一顿完整的饭。这直接反映在2/10的留存意愿上，用户认可能力，但不认可体验。

核心教训

AI产品的价值不在于"能做什么"，而在于"在什么场景下、以什么路径、自动帮用户做到什么"。Skill是能力单元，但用户购买的从来不是能力，而是场景闭环。下一阶段的迭代重心，应该是把散点能力编织成"持仓记忆 → 个性化盯盘 → 微信推送 → 追问深挖"的完整闭环，而非继续横向铺新Skill。

这一点与AI产品经理岗位所要求的产品理念高度一致，"把海量信息压缩成有信息量的判断线索"，重点不是信息量本身，而是加工和解读的路径是否通畅。

4.2 Skill生态策略修正：从「全面铺开」到「极客先行」

这是我在实习过程中最重要的一个方向性修正。

初期的策略偏差：Claw在Skill生态建设初期，试图面向所有用户全面铺开Skill种类，什么品类都做、什么场景都覆盖，寄望于"足够全的Skill矩阵"自然吸引用户。但访谈数据打脸了这个假设：用户反馈"skill齐全但不知道怎么用""字小、同质化、分类无效、无探索欲"。全面铺开的结果是，什么都有，但什么都不精，用户什么都不想用。

修正方向：投资对的方向，极客先行。经过访谈和复盘，我判断Skill生态在初期应该走一条"极客写Skill → 渗透投资心智用户 → 真实评价与口碑传播 → 吸引普通用户"的渐进路径，而非一步到位铺向所有人：

第一步 极客写Skill
让有技术能力+投资经验的极客用户贡献Skill，构建高质量能力池
→
第二步 渗透投资心智用户
有投资心智的早期用户率先使用，产生真实使用数据和反馈
→
第三步 口碑传播获认可
基于真实使用评价，极客和早期用户自发宣传，形成信任背书
→
第四步 吸引普通用户
普通用户被真实口碑吸引进入，降低冷启动的教育成本
为什么这条路径是对的：
  • 信任问题先解决：金融AI最大的门槛不是功能，是信任。极客和投资心智用户具备判断Skill质量的能力，他们的真实评价本身就是信任背书。有用户提出"数据真伪验证+信息源可跳转"是AI理财的信任基础，而极客先行策略本质上就是在用真实用户的使用验证来构建这层信任。
  • Skill质量有筛选机制：极客写Skill → 早期用户用 → 真实评价筛选 → 好Skill存活、差Skill淘汰。这比产品经理拍脑袋决定做哪些Skill更可靠，也更有生态自驱力。
  • 教育成本后置：普通用户不需要理解Skill是什么，他们只需要看到"别人用了觉得好"，然后直接用结果。这恰好对应用户反馈"习惯点-看而非点-问-等"，先让极客把"问"的能力建好，普通用户只需要"看"结果。

这条路径的本质，是区分"能力建设阶段"和"规模推广阶段"的用户策略。这与AI产品经理岗位JD中"分辨哪些是机构视角遗留的伪需求、哪些是普通用户真正的痛点"高度共鸣，极客和投资心智用户帮我们辨别了真需求，而普通用户需要的是被验证过的好结果，而非更多功能选项。

4.3 Agent Harness反思：何时给结论、何时承认不确定

访谈中暴露的一个深层问题来自Agent的行为逻辑：用户反馈"模型思考后选择追问而非直接输出""非交易时段依旧输出当下买卖操作建议""幻觉问题（时间错误等）"。这些表面是Bug，底层是Agent harness在「给结论 vs 追问 vs 承认不确定」之间的判断逻辑尚未调优。

产品视角的思考

金融场景对Agent的要求远高于通用场景：什么时候应该给明确结论（用户问了持仓盈亏，就该直接报数）、什么时候应该追问（用户意图模糊时）、什么时候必须承认不确定（预测类问题必须标注假设和风险）。这不是纯算法问题，而是需要产品侧定义清晰的场景规则和输出标准，什么场景下模型应该"有观点但不虚构"，什么场景下应该"给出判断线索而非确定性建议"。

这正是AI产品经理岗位JD中"和算法一起打磨大模型的加工与解读能力，什么时候给结论、什么时候承认不确定性"要解决的核心问题。我在Claw的实践中已经触碰到了这个问题，并形成了初步的产品侧思考框架。

4.4 用户洞察方法论反思：分辨真需求与伪需求

75条问题中，有大量"用户说要做什么"的需求，但并非所有都值得做。通过这轮访谈，我形成了几个判断原则：

  • "想不起要打开"比"功能不够"更致命。2/10的留存意愿背后，核心原因不是功能缺失，而是没有打开理由。定时任务+微信推送的闭环，本质上是在制造"打开理由"，不是让用户主动来，而是让结果主动找用户。
  • "点-看"优于"点-问-等"。用户反馈习惯直接点击看结果而非提问等待。这提示我们：AI native不等于必须"对话优先"，在行情展示等场景中，AI应该在后台加工，前端以"看"的形态交付结果，对话是深挖入口而非唯一路径。
  • "持仓记忆"是一切个性化的前提。没有持仓数据，所有分析都是通用的。这不是一个功能需求，而是产品的基础设施，它应该渗透到每个模块，而非做成一个独立入口。

这些判断与AI产品经理岗位"从用户根本需求出发，定义并迭代核心金融场景的产品能力"的岗位要求直接对应，不是用户要什么就做什么，而是从根本需求出发翻译成产品方案。
